## 核心工作流限制 (Git 操作与开发模式)
1. **默认开发模式**：项目默认使用 `dev` 开发模式进行所有设计与开发。非经男神欧巴明确下达类似“转换成 prod 生产模式”的指令，绝对不得擅自更改运行环境与相关生产配置。  
2. **每次会话强制本地记录**：**每次会话**的代码开发、修改或文档更新完成后，必须无条件通过 Git 进行本地记录。  
3. **包含特定敏感与数据目录**：由于处于 `dev` 开发模式，在执行本地 Git 记录时，**必须且强制包含 `.env` 配置文件以及 `data/` 文件夹内的所有文件**，以确保开发上下文的绝对完整。请在 `git add` 时注意不要将其忽略。  
4. **仅限本地提交**：在每次会话完成后，你只能使用 `git add` 和 `git commit` 将更改记录到本地仓库。请务必书写清晰、符合规范的 commit message。  
5. **禁止自动推送**：**绝对不要**自动执行 `git push` 或推送到 any 远程仓库。推送到 GitHub 的操作，必须且只能在男神欧巴明确下达类似“推送代码到 GitHub”的指令后才能执行。  

## 文档同步更新机制 (Commit 前置强制检查)
每次代码变更或完成阶段性任务后，**在进行本地 `git commit` 之前**，你必须强制检查并更新以下五个核心文档。请注意，除 README 外，其余核心文档均统一管理于 `docs/` 目录中：  
1. **`docs/` 架构设计文档**：若涉及系统结构、核心流程或数据库变动，必须在 `docs/` 目录下生成或更新对应的架构设计文档。  
2. **`docs/project_skill.md` [项目技能文档]**：记录本次开发中新引入的技术栈、解决的复杂技术难点、踩坑记录或使用的特定工具命令。  
3. **`docs/REQUIREMENTS.md` [需求文档]**：核对本次修改对应的需求，更新需求的状态（如：将对应需求标记为“已完成”），并补充在开发过程中衍生出的新需求或优化点。  
4. **`docs/handoff.md` [上下文交接文档]**：在阶段性任务结束或会话中断前，强制更新此文档。需精简记录当前开发进度、未完结的待办事项（Todo List）、下一步行动计划以及当前环境的特定状态，作为后续会话或其他 Agent 接入时的无缝交接依据。  
5. **`README.md` [项目说明文档]**：根据本次的代码迭代，同步更新项目的最新状态、功能说明、运行步骤或架构变化。
